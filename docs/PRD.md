## 1. 한 줄 요약

**영상 파일을 넣으면 음량 밸런스와 자막을 자동으로 정리하고, 채팅으로 자막 문법과 튀는 음량을 다듬은 뒤, 다빈치 리졸브(무료판)에서 바로 이어서 편집할 수 있는 형태로 넘겨주는 윈도우 데스크톱 앱.**

## 2. 배경과 문제

유튜브 롱폼 영상을 만들 때 편집 시간의 상당 부분이 판단이 필요 없는 **반복 작업**에 쓰입니다. 그중에서도 가장 부담이 큰 것은 **음량 밸런스 조절**입니다.

- 영상마다, 구간마다 목소리 크기가 들쭉날쭉하다.
- 웃음·박수·갑자기 큰 소리처럼 튀는 부분을 하나하나 찾아 낮춰야 한다.
- 자막을 받아 적은 뒤 맞춤법·띄어쓰기를 일일이 고쳐야 한다.

이 작업들을 자동화하고, 사람의 판단이 필요한 부분은 채팅으로 짧게 지시해서 처리한 다음, 창의적인 마무리 편집은 익숙한 다빈치 리졸브에서 하도록 하는 것이 목표입니다.

## 3. 목표와 비목표

### 3.1 목표

1. **음량 자동 정리:** 영상을 넣으면 사람 손 없이 음량 밸런스가 맞춰진 오디오가 나온다.
2. **자막 자동 생성:** 한국어 음성을 받아 적어 자막(SRT)을 만든다.
3. **채팅으로 다듬기:** "자막 맞춤법 고쳐줘", "2분쯤 튀는 소리 잡아줘"처럼 말로 지시하면 반영된다.
4. **리졸브로 넘기기:** 결과를 다빈치 리졸브 무료판에서 바로 불러와 이어서 편집할 수 있다.
5. **판매 가능한 구조:** 처음부터 다른 사람의 PC에서도 설치·실행될 수 있게 만든다.

### 3.2 비목표 (이번 범위에서 하지 않는 것)

- 리졸브를 대체하는 완성형 편집기 (컷 연출, 효과, 색보정은 리졸브에서)
- 다빈치 리졸브 Studio(유료판) 전용 기능 (리졸브 직접 조종 등)
- 웹 서비스, 맥/리눅스 지원, 모바일 앱
- 클라우드 서버에서 영상 처리

## 4. 사용자와 사용 환경

| 항목 | 내용 |
| --- | --- |
| 1차 사용자 | 오문성 본인 (유튜브 롱폼 채널 운영 예정) |
| 향후 사용자 | 이 앱을 구매하는 유튜버·편집자 (판매 고려) |
| 영상 유형 | 유튜브 롱폼. 장르는 아직 정하지 않았으므로 **특정 장르에 묶이지 않는 범용 구조** |
| 운영체제 | **윈도우 전용** (Windows 10/11, 64비트) |
| 처리 위치 | **사용자 PC에서 모두 처리** (영상이 외부로 나가지 않음) |
| PC 사양 | 사용자마다 다름 → 앱이 사양을 자동 감지해서 맞춤 (7.3절) |
| 마무리 편집 | **다빈치 리졸브 무료판** |

## 5. 핵심 사용자 흐름

```
① 앱 실행 → 영상 파일 열기 (업로드 없음, 내 PC 파일 그대로)
      ↓
② 자동 처리 (진행률 표시)
   - 음량 분석 → 음량 밸런스 자동 조절
   - 한국어 받아쓰기 → 자막 생성
      ↓
③ 결과 확인 화면
   - 음량 그래프 (처리 전/후 비교, 튀는 구간 표시)
   - 자막 목록 (시간 + 문장)
   - 미리 듣기/미리 보기
      ↓
④ 채팅으로 다듬기  ←──────────────┐
   "자막 맞춤법 전체 검사해줘"        │
   "2분 10초쯤 웃음소리 너무 커"       │ 반복
   "전체적으로 튀는 부분 정리해줘"      │
      ↓                             │
⑤ 변경 내용 확인 → 적용 / 취소 ─────┘
      ↓
⑥ 리졸브로 내보내기
   - 타임라인 파일(FCPXML) + 정리된 오디오(WAV) + 자막(SRT)
      ↓
⑦ 다빈치 리졸브에서 타임라인 불러오기 → 마무리 편집
```

### 6.3 채팅으로 다듬기

인터뷰에서 정한 채팅 편집의 핵심은 **자막 문법 교정**과 **튀는 음량 조절** 두 가지입니다.

| ID | 기능 | 예시 문장 | 우선순위 |
| --- | --- | --- | --- |
| C-01 | 자막 문법 교정 | "자막 맞춤법 전체 검사해줘" → 고칠 목록 제시 → "전부 적용" 또는 골라서 적용 | P0 |
| C-02 | 자막 개별 수정 | "3분쯤 '되요'를 '돼요'로 고쳐줘", "'클로드'로 전부 바꿔" | P0 |
| C-03 | 구간 음량 조절 | "2분 10초쯤 웃음소리 너무 커", "5분~6분 목소리 좀 키워줘" | P0 |
| C-04 | 전체 음량 정리 | "전체적으로 튀는 부분 정리해줘", "튀는 거 좀 덜 잡아줘" | P0 |
| C-05 | 되돌리기 | "방금 거 취소", "처음 상태로" | P0 |
| C-06 | 변경 요약 | 적용할 때마다 무엇이 바뀌었는지 한두 줄로 보여줌 | P0 |
| C-07 | 되묻기 | 요청이 모호하면 적용 전에 확인 ("2분 10초 전후 5초를 -6dB 낮출까요?") | P1 |
| C-08 | 말로 위치 지정 | "'여기까지 하겠습니다' 부분 소리 키워줘" (자막을 이용해 위치를 찾음) | P1 |

**채팅 처리 원칙**
- AI는 영상을 직접 건드리지 않습니다. 정해진 **편집 명령(8장)** 만 만들고, 실제 적용은 앱의 편집 엔진이 합니다. 그래서 결과가 예측 가능하고 잘못된 명령은 걸러집니다.
- AI에게는 영상이 아니라 **자막 텍스트와 음량 분석 요약**만 보냅니다. 비용이 적게 들고 영상이 외부로 나가지 않습니다.
- 모든 변경은 되돌릴 수 있습니다.

### 6.4 다빈치 리졸브 연동

리졸브 무료판은 외부 프로그램이 리졸브를 직접 조종하는 스크립팅 기능을 제대로 지원하지 않습니다(Studio 전용). 그래서 **파일로 넘기는 방식**을 씁니다. 이 방식은 무료판·Studio 모두에서 동작합니다.

| ID | 기능 | 설명 | 우선순위 |
| --- | --- | --- | --- |
| R-01 | 정리된 오디오 내보내기 | 음량 처리가 끝난 오디오를 WAV로 저장 | P0 |
| R-02 | 자막 내보내기 | SRT 파일 저장 | P0 |
| R-03 | 타임라인 파일 내보내기 | 원본 영상 + 정리된 오디오 + (컷이 있으면 컷 정보)를 담은 FCPXML 생성. 리졸브에서 `파일 → 가져오기 → 타임라인`으로 불러옴 | P1 |
| R-04 | 리졸브 불러오기 안내 | 내보내기 후 리졸브에서 불러오는 방법을 앱 안에서 안내 | P1 |
| R-05 | 완성 영상 직접 내보내기 | 리졸브 없이 이 앱에서 바로 mp4로 뽑기 (간단한 영상용) | P2 |

## 7. 시스템 구조

### 7.1 전체 구조

```
┌──────────────── 윈도우 데스크톱 앱 ─────────────────┐
│                                                     │
│  [화면(UI)]  영상 열기 · 음량 그래프 · 자막 목록 · 채팅   │
│       │                                             │
│       ▼                                             │
│  [편집 엔진]  ← 모든 작업은 "편집 명령"으로 들어옴         │
│    ├─ 음량 처리   (FFmpeg 오디오 필터)                  │
│    ├─ 받아쓰기    (faster-whisper, GPU/CPU 자동)        │
│    ├─ 편집 상태   (명령 이력, 되돌리기)                   │
│    └─ 내보내기    (WAV · SRT · FCPXML)                 │
│       │                                             │
└───────┼─────────────────────────────────────────────┘
        │ 자막 텍스트 + 음량 요약만 전송
        ▼
   [AI 서비스]  채팅 → 편집 명령 변환, 자막 문법 교정
        (사용자가 입력한 AI 키 사용)

   내보낸 파일 ──▶ 다빈치 리졸브 무료판에서 불러오기
```

**화면과 편집 엔진을 분리**하는 것이 장기 운영의 핵심입니다. 엔진은 화면 없이도 명령줄에서 돌아가게 만들어 먼저 검증하고, 화면은 그 위에 얹습니다. 나중에 화면 기술을 바꿔도 엔진은 그대로 씁니다.

### 7.2 기술 스택 [제안]

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 언어 | Python 3.11+ | 영상·음성·AI 라이브러리가 가장 풍부 |
| 화면(UI) | PySide6 (Qt) | 윈도우 네이티브 앱, 파이썬 하나로 엔진과 화면을 모두 개발, 상용 배포 가능(LGPL) |
| 영상/음성 처리 | FFmpeg | 음량 정규화(loudnorm), 압축·리미터 등 음량 처리에 필요한 기능이 모두 있음 |
| 받아쓰기 | faster-whisper | 한국어 품질 양호, 단어 단위 시간 정보, NVIDIA GPU 가속 지원 |
| 채팅·문법 교정 | Claude API (tool use) | 한국어 이해력, 정해진 명령 형식으로 출력 가능 |
| 프로젝트 저장 | 프로젝트 폴더 안의 JSON 파일 | 단순하고 백업·이동이 쉬움 |
| 설치 파일 | 개발 중: PyInstaller / 판매용: Nuitka + 윈도우 설치 프로그램(Inno Setup 등) | .exe 설치형 배포. Nuitka는 파이썬 코드를 기계어로 컴파일해 코드 노출을 줄임 |

**다른 선택지와 비교**

| 선택지 | 장점 | 단점 | 판단 |
| --- | --- | --- | --- |
| **Python + PySide6** | 엔진·화면·AI를 한 언어로 개발. 음성·AI 새 기술이 파이썬으로 가장 먼저 나옴 | 설치 파일이 큼, 화면을 아주 화려하게 꾸미기엔 웹 기술보다 불리 | **채택** (1인 개발 + AI 중심에 가장 적합) |
| C# (.NET, WPF/WinUI) | 윈도우 전용 상용 앱의 정석, 설치·서명·업데이트 도구가 성숙 | 받아쓰기·AI 라이브러리가 부족해 결국 파이썬을 뒤에 붙여야 함 → 두 언어 관리 | 보류 |
| Electron/Tauri + Python 엔진 | 화면을 웹 기술로 자유롭게, 디자인 자원이 풍부 | 화면(JS/TS)과 엔진(Python) 두 언어, 둘 사이 통신 코드 필요 | 화면 교체가 필요해지면 재검토 (7.4의 엔진 분리 덕분에 가능) |

무거운 작업(음량 처리, 받아쓰기)은 FFmpeg와 faster-whisper 내부의 C/C++ 코드가 처리하고 파이썬은 작업을 지시만 하므로, "파이썬은 느리다"는 점은 이 앱에서 거의 문제가 되지 않습니다.

| # | 원칙 | 구체적으로 | 얻는 것 |
| --- | --- | --- | --- |
| 1 | 엔진 독립 | `engine/` 패키지는 화면 코드를 전혀 모르고, 명령줄·테스트·화면 어디서든 같은 함수로 호출 | 화면을 PySide6에서 다른 기술로 바꿔도 엔진은 그대로 |
| 2 | 명령 등록 방식 | 새 편집 기능 = 편집 명령 하나 + 처리 함수 하나를 등록하면 끝. 기존 코드 수정 불필요 | 기능을 계속 늘려도 코드가 엉키지 않음 |
| 3 | 형식에 버전 번호 | 편집 명령 스키마와 프로젝트 파일에 `schema_version`을 넣고, 버전이 바뀌면 자동 변환(마이그레이션) | 앱을 업데이트해도 예전 프로젝트가 열림 (판매 후 필수) |
| 4 | 교체 가능한 외부 의존 | AI(Claude API), 받아쓰기 모델, FFmpeg 호출을 각각 한 모듈 뒤에 숨김 | AI 비용 방식이나 모델을 바꿔도 다른 코드는 그대로 |
| 5 | 자동 테스트 | 샘플 음원으로 "처리 후 -14 LUFS ±1, 최대치 -1 dBTP 이하"를 매번 자동 확인. GitHub Actions의 윈도우 환경에서 실행 | 기능을 고쳐도 음량 결과가 망가지지 않았는지 바로 확인 |
| 6 | 원본 불변 + 작업 로그 | 원본은 읽기만, 모든 처리 과정과 오류를 로그 파일로 남김 | 사용자 PC에서 난 문제를 재현·지원 가능 |
| 7 | 라이선스 관리 | 사용하는 라이브러리와 라이선스를 `docs/licenses.md`에 목록화 (PySide6·FFmpeg는 LGPL 조건 준수) | 판매 시점에 라이선스 문제로 막히지 않음 |

### 7.3 PC 사양 자동 감지

판매까지 고려하면 사용자마다 PC가 다르므로, 앱이 처음 실행될 때 사양을 확인해 처리 방식을 고릅니다.

| 감지 결과 | 처리 방식 |
| --- | --- |
| NVIDIA 그래픽카드(CUDA 사용 가능) | 받아쓰기를 GPU로 처리 (빠름) |
| NVIDIA 없음 | CPU 모드, 더 작은 받아쓰기 모델 사용 (느리지만 동작) |
| 메모리 부족 | 긴 영상을 나눠서 처리 |

설정 화면에서 사용자가 직접 바꿀 수도 있게 합니다.

## 8. 핵심 설계: 편집 명령

자동화와 채팅이 모두 같은 형식의 **편집 명령**을 만들고, 편집 엔진은 이 명령 목록만 보고 결과를 만듭니다. 되돌리기는 명령 목록을 이전 버전으로 돌리는 것으로 처리합니다.

```json
{ "op": "normalize_loudness", "target_lufs": -14, "true_peak": -1 }
{ "op": "tame_peaks", "range": "all", "threshold_db": -6, "strength": "medium" }
{ "op": "gain", "start": 128.0, "end": 135.0, "db": -6, "reason": "채팅: 2분 10초쯤 웃음소리 너무 커" }
{ "op": "subtitle_edit", "id": "sub_042", "text": "돼요" }
{ "op": "subtitle_replace_all", "from": "클러드", "to": "클로드" }
```

- 시간은 **원본 영상 기준 초**로 저장합니다.
- 명령 형식은 JSON Schema로 정의하고, AI 도구 호출(tool use)의 입력 형식으로도 그대로 씁니다.
- 명령마다 `reason`(왜 바뀌었는지)을 남겨 변경 요약과 이력 화면에 씁니다.

## 9. 단계별 로드맵

각 단계는 **완료 기준을 만족해야 다음 단계로** 넘어갑니다. 단계마다 PR 단위로 진행합니다.

### 0단계. 준비

- 범위: 저장소 구조(`engine/`, `app/`, `docs/`, `samples/`, `tests/`), 윈도우 개발 환경(Python, FFmpeg), 테스트용 샘플 영상 3개(조용한 영상 / 소리 튀는 영상 / 20분 이상 긴 영상), 편집 명령 JSON Schema v0(`schema_version` 포함), 자동 테스트 틀과 GitHub Actions 윈도우 실행 설정
- 완료 기준: 명령줄에서 샘플 영상의 길이, 해상도, 오디오 정보가 출력된다.

### 1단계. 음량 밸런스 엔진 (첫 번째 목표)

- 범위: A-01~A-04, R-01. 화면 없이 명령줄로 동작
- 예시: `python -m engine balance input.mp4` → 정리된 WAV + 처리 전/후 음량 리포트
- 완료 기준: 샘플 3개 모두 -14 LUFS ±1 이내, 최대치 -1 dBTP 이하. 튀는 구간이 귀로 들었을 때 확실히 줄어들고, 목소리가 찌그러지지 않는다.

### 2단계. 자막 + 리졸브 연동

- 범위: S-01~S-03, R-02, R-03, G-03(사양 감지)
- 완료 기준: 10분 영상을 넣으면 정리된 오디오 + SRT + FCPXML이 나오고, **리졸브 무료판에서 타임라인으로 불러오면 영상·오디오·자막이 제자리에 올라온다.**

### 3단계. 데스크톱 앱 화면

- 범위: G-01, G-02, G-04, G-05, 음량 그래프, 자막 목록, 미리 듣기, A-05, A-06
- 완료 기준: 명령줄 없이 앱에서 영상 열기 → 자동 처리 → 결과 확인 → 리졸브용 내보내기까지 된다.

### 4단계. 채팅으로 다듬기

- 범위: C-01~C-08, AI 키 입력(사용자 키 방식)
- 완료 기준: 준비한 테스트 문장 30개(문법 교정, 구간 음량, 전체 음량, 취소 등) 중 90% 이상이 의도대로 반영된다. 모호한 요청은 적용 전에 되묻는다.

### 5단계. 실사용 검증

- 범위: 실제 유튜브 영상 3편을 이 앱 + 리졸브로 완성, 불편한 점 개선, S-04(단어 사전)
- 완료 기준: 기존 방식 대비 편집 시간을 기록하고, 음량·자막 작업 시간이 절반 이하로 줄었는지 확인한다.

### 6단계. 판매 준비

- 범위: 설치 프로그램(.exe), 자동 업데이트, 라이선스(구매 확인), 사용 설명서, 다양한 PC 사양 테스트
- 이 단계에서 결정: AI 비용 부담 방식(11장), 가격, 판매 채널
- 이후 확장 후보: 배경음악 자동 조절(A-07), 잡음 줄이기(A-08), 완성 영상 직접 내보내기(R-05), 무음 구간 자동 컷, 챕터 타임스탬프 생성

```
0단계 ─▶ 1단계 ─▶ 2단계 ─▶ 3단계 ─▶ 4단계 ─▶ 5단계 ─▶ 6단계
 준비    음량엔진   자막+리졸브  앱 화면    채팅     실사용    판매 준비
         └──────── 여기까지가 "내가 쓸 수 있는 첫 버전" ────────┘
```

## 11. AI 비용 정책

- **현재 결정:** 사용자가 자신의 AI(Claude API) 키를 설정 화면에 입력해서 쓰는 방식으로 시작합니다.
- **판매 단계에서 재결정:** 사용자 키 방식 유지 / 구독료에 AI 비용 포함 / PC에서 도는 로컬 AI 모델 중에서 6단계에 다시 정합니다.
- 이를 위해 AI 호출 부분은 한 곳(모듈)에 모아 두어, 나중에 방식을 바꿔도 다른 코드는 손대지 않게 합니다.
- 채팅 1회당 사용한 토큰·비용을 기록해 판매 가격 결정에 참고합니다.
